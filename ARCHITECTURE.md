# Архитектура

Документ описывает устройство проекта: из чего он состоит, как проходит запрос,
какие решения приняты и почему. README отвечает на вопрос «как пользоваться»,
этот файл — на вопрос «как это устроено и что будет, если менять».

## Слои

```
        cli.py                 web.py + templates/index.html
           \                          /
            \                        /
             +----- agent/__init__ --+          ← публичная граница
                        |
             DocumentAnalysisAgent (agent/agent.py)
                        |
   +--------+-----------+-----------+------------+----------+
   |        |           |           |            |          |
catalog  memory    compression   tokens      doc_readers   fsbu
 модели  история   выжимки      подсчёт      PDF/DOCX/XLSX  правила
         SQLite                 контекста                   учёта
                        |
                     prompts, schemas, report
```

Правило границы одно: **интерфейсы знают только про агента**. Ни `cli.py`, ни
`web.py` не импортируют `httpx`, не видят промптов, не знают адреса провайдера
и не обращаются к приватным методам. Это не пожелание, а проверяемое условие —
в `tests.py` есть группа, которая читает исходники интерфейсов и падает, если
граница нарушена.

## Модули

| Модуль | Отвечает за | Не знает про |
|--------|-------------|--------------|
| `agent/agent.py` | Сборку запроса, вызов LLM, разбор ответа, память, бюджет, сжатие | Формат PDF, правила ФСБУ, устройство Excel |
| `agent/catalog.py` | Модели: адрес, ключ, окно контекста, цены, коэффициент токенизатора | Диалог, документы |
| `agent/memory.py` | Хранение сообщений и выжимок в SQLite | LLM, промпты |
| `agent/compression.py` | Промпты сжатия и оформление выжимки | HTTP, базу |
| `agent/tokens.py` | Оценку токенов, бюджет контекста, деньги | Модели, историю |
| `agent/doc_readers.py` | Чтение PDF, DOCX, XLSX | ФСБУ, LLM |
| `agent/fsbu.py` | Категорию, счёт, лимит, амортизацию | LLM, интерфейсы |
| `agent/prompts.py` | Системные промпты предметной области | Всё остальное |
| `agent/schemas.py` | Форму результата и защищённый разбор ответа модели | HTTP |
| `agent/report.py` | Сводную таблицу Excel | LLM |

## Путь запроса

Что происходит при `agent.ask("вопрос")`:

1. **Проверка на пустоту.** Пустой запрос до сети не доходит.
2. **`_maybe_compress()`** — решает, пора ли сворачивать давние реплики.
   Условий два, срабатывает наступившее раньше: накопилось `compress_every`
   состарившихся сообщений либо история заняла больше `compress_threshold`
   доли контекста. Сжатие — отдельный вызов к дешёвой модели.
3. **`_history_for_model()`** — собирает контекст: выжимка отдельным системным
   сообщением плюс все ещё не свёрнутые реплики дословно.
4. **`_fit_history()`** — сверяет бюджет с окном модели. Если не помещается,
   применяется политика `on_overflow`: обрезать, отказать или отправить как есть.
5. **`_call_llm()`** — единственное место с HTTP. Повторы при сетевых сбоях,
   ожидание при 429 и 413 по заголовку `retry-after`.
6. **`_extract_answer()`** — достаёт текст и точный расход из `usage`,
   считает стоимость и расхождение с предварительной оценкой.
7. **`_remember()`** — пара «вопрос — ответ» с токенами и стоимостью ложится
   в SQLite.

Разбор документа (`analyze`) идёт мимо истории диалога, но его итог попадает
в неё сжатой сводкой — чтобы по документу можно было задавать вопросы потом.

## Хранилище

Две таблицы в одном файле SQLite.

`messages` — сырой разговор. Никогда не удаляется при сжатии: это источник
истины, из которого выжимку всегда можно собрать заново.

`summaries` — поколения выжимок. У каждой записан `covers_until` — номер
последнего свёрнутого сообщения. Всё, что новее, уходит в запрос дословно.
Старые поколения не стираются: по ним видно, как менялся конспект.

Схема расширяется миграцией на месте (`_migrate`): базы прежних дней
открываются без потери данных, недостающие колонки дописываются.

## Принятые решения

Каждое решение — с причиной и с ценой, которую оно за собой тянет.

### Р-1. Категорию учёта считает код, а не языковая модель

Модель читает документ и отвечает на пять вопросов «да/нет»; категорию, счёт,
лимит и амортизацию вычисляет `agent/fsbu.py`.

*Почему.* Арифметика и сопоставление с порогом требуют воспроизводимости, а не
правдоподобия. Модель даже не просят вернуть категорию: чего не просим, то и не
придётся перепроверять.

*Цена.* Правила приходится поддерживать в коде вручную при изменении стандарта.

### Р-2. История в SQLite, а не в JSON

*Почему.* Модуль `sqlite3` входит в стандартную библиотеку, запись атомарна,
процесс, убитый посреди сохранения, не оставляет испорченный файл. JSON
переписывался бы целиком на каждом сообщении.

*Цена.* Историю нельзя открыть текстовым редактором — нужен просмотрщик SQLite.

### Р-3. Выжимку делает отдельная дешёвая модель

*Почему.* Сжатие — работа механическая. На платной основной модели выжимки
съедали бы часть той экономии, ради которой всё затевается.

*Цена.* Две модели в настройках вместо одной; стиль выжимки может отличаться
от тона основного диалога.

### Р-4. Выжимка накатывается, а не собирается заново

Новая выжимка делается из предыдущей плюс реплик, состарившихся с прошлого раза.

*Почему.* Дёшево и работает при любой длине разговора. Полная пересборка на
длинном диалоге упёрлась бы в то же контекстное окно, которое мы пытаемся
разгрузить.

*Цена.* Эффект испорченного телефона: детали размываются от поколения к
поколению. Смягчение — сырые сообщения не удаляются, и команда «пересобрать»
(`rebuild_summary`) строит конспект заново за один проход.

### Р-5. Оценка токенов — эвристика, а не токенизатор

*Почему.* Настоящий токенизатор — отдельная зависимость со словарями на десятки
мегабайт и своя для каждого семейства моделей. Оценка по классам символов
с коэффициентом на модель даёт среднюю ошибку около 2%.

*Цена.* Оценка остаётся оценкой: на границе контекста нужен запас. Точное число
приходит только в `usage` ответа, то есть уже после запроса.

### Р-6. Сжатие никогда не роняет разговор

Если модель-сжиматель недоступна или вернула пустой ответ, ошибка пишется в
журнал, а разговор продолжается на полной истории.

*Почему.* Сжатие — вспомогательная функция. Ронять из-за неё основную работу
нельзя.

*Цена.* После неудачного сжатия запрос остаётся крупным, и следующий вызов
может упереться в минутный лимит расхода у провайдера. Поэтому предупреждение
в журнале сформулировано явно.

## Что легко поменять

- **Добавить модель** — одна запись в `agent/catalog.py`. Нужны окно контекста
  (эндпоинт `/models` провайдера), цены и коэффициент токенизатора (измеряется
  одним текстом, см. README).
- **Сменить предметную область** — переписать `agent/prompts.py` и
  `agent/fsbu.py`; остальное к бухгалтерии не привязано.
- **Заменить хранилище** — `agent/memory.py` общается с агентом через десяток
  методов; их достаточно реализовать поверх другой базы.
- **Изменить стратегию сжатия** — `agent/compression.py` задаёт промпты,
  `_maybe_compress` в агенте задаёт правило запуска.

## Чего в проекте намеренно нет

- **Асинхронности.** Агент синхронный: интерфейсы однопользовательские, а
  простота отладки важнее пропускной способности.
- **Векторного поиска по истории.** Для длинных разговоров он был бы уместнее
  выжимки, но это уже другая задача.
- **Аутентификации в вебе.** Сервис поднимается на `127.0.0.1` и рассчитан на
  одного пользователя за своим столом.
- **Шифрования истории.** В базе лежат тексты вопросов и сводки по документам;
  защита — файловые права и `.gitignore`.
